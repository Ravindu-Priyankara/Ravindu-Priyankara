## Selected Investigations & Contributions

### 01. Falco — eBPF Bytecode Optimization

**~6 lines of C. 32 fewer eBPF instructions per syscall event across 87 probe sites.**

My first merged open-source contribution to `falcosecurity/libs`.

The investigation traced unnecessary bytecode instructions to writes through an unaligned pointer to a packed structure. Moving the structure to the stack and using `__builtin_memcpy` allowed the compiler to generate more efficient stores.

- **Result:** 32 fewer eBPF instructions per syscall event across 87 probe sites.
- **Status:** Merged.
- **Evidence:** [Merged pull request](https://github.com/falcosecurity/libs/pull/3022) · [Technical write-up](https://ravindu-priyankara.hashnode.dev/squeezing-bytes-how-i-optimised-an-ebpf-driver-in-falco)

### 02. Falco — Cross-Compiler eBPF Optimization

**Five Clang versions. Five measured reductions. Up to 43 fewer instructions.**

Investigated another eBPF optimization in the `shutdown_x` sensor and compared translated BPF instruction counts before and after the change.

| Clang version | Before | After | Reduced |
|---|---:|---:|---:|
| clang-14 | 344 | 310 | 34 |
| clang-17 | 323 | 289 | 34 |
| clang-18 | 334 | 300 | 34 |
| clang-19 | 334 | 300 | 34 |
| clang-20 | 355 | 312 | 43 |

The changes explored helper functions for storing header fields and examined how different Clang versions generated BPF instructions.

The PR was closed after a compatibility issue on an older Fedora 5.8 kernel remained unresolved. The measured code-generation results are documented separately from the unmerged status.

- **Result:** 34–43 fewer instructions in the tested output.
- **Status:** Closed; not merged.
- **Evidence:** [PR discussion and test results](https://github.com/falcosecurity/libs/pull/3026)

### 03. Tetragon — Loader Error-Handling Bug

Investigated a failure path in `bpf/process/bpf_loader.c` involving `probe_read_str()`.

When the helper returned a non-positive value, the loader could continue with an invalid path length. The upstream fix checks the return value before setting the path size and continuing.

- **Area:** eBPF tracing and loader event handling.
- **Result:** Upstream error-handling fix.
- **Evidence:** [Upstream commit `c6e9216`](https://github.com/cilium/tetragon/commit/c6e92166fbdcc309e183c8ac600314f761908329)

## How I Work

I tend to start with a simple question:

> **"What actually happens here?"**

Then I follow it.

```text
Source
  ↓
Compiler
  ↓
Assembly / BPF bytecode
  ↓
Registers and memory
  ↓
Kernel APIs
  ↓
Runtime behavior
```

I use `GDB`, `radare2`, `LLVM`, `objdump`, `readelf`, `pahole`, `bpftool`, `bpftrace`, and `QEMU` — whatever helps me verify what's actually happening.

I prefer evidence over assumptions: source code, disassembly, memory layouts, traces, and reproducible experiments.
